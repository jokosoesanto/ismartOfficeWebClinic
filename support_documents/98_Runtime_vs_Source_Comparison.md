# Runtime vs Source Code Comparison

This document highlights the discrepancies between what exists in the Source Code and what actually executes during Runtime rendering.

## Discrepancy Map

| Category | Finding | Evidence |
|---|---|---|
| **Dibuat tetapi tidak pernah dipanggil** | None | All template files are requested correctly by the `return View("Templates/...")` statements. The View Engine successfully parses all of them. |
| **Dipanggil tetapi tidak pernah ada** | None | The previous sprint fixed all `InvalidOperationException` issues. All templates physically exist in the `Views/Shared/Templates/` directory. |
| **Sudah ada namun tertimpa** | **ALL Templates** | The HTML source of every new template is fully generated by the Razor engine, but the Layout (`_RegionLayout.cshtml`) calls `IgnoreBody()` before appending it to the final response. The rendered bytes are simply discarded from memory. |
| **Isi akhirnya berasal dari ViewComponent lain** | **ALL Pages** | Because `IgnoreBody()` was called, the layout iterated over the Controller's `UIMetadata.Composition.Center` and appended the output of the Legacy ViewComponents (`PrototypeDashboard`, `DataGrid`, `PrototypeTransaction`, etc.). |

## Code Conflict Example

Source Code: `Patient_List.cshtml` expects to render a table of patients.
```html
<h2 class="mb-0 fw-bold">Patient Management</h2>
<!-- New table layout -->
```

Runtime Result: `DataGrid` ViewComponent is rendered instead.
```html
<h5><i class="bi bi-people me-2 text-primary"></i> Registered Patients</h5>
<!-- Old table layout -->
```

## Resolution Path (For the next sprint)
To resolve this discrepancy, the Framework must either:
1. Update all Controllers to stop passing Legacy ViewComponents to `Composition.Center`.
2. Update the `_RegionLayout.cshtml` to stop calling `IgnoreBody()`, allowing `RenderBody()` to run alongside or instead of `Composition.Center`.
